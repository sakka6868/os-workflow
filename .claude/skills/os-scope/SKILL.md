# os-scope：需求澄清 + 范围界定

## 何时调用

新功能、API 变更、任何描述少于一句话或涉及多模块交互的请求。需求不明确时优先调用。

## 核心原则

**一次只问一个问题，优先给多选题。** 不要一次性抛出一串问题——用户面对问题轰炸会跳过或敷衍。每轮只问一个最关键的，得到答案后再问下一个。能列出 2-3 个选项的优先用选择题，降低用户回答成本。

## 场景三问（逐个问）

1. **给谁用** — 目标角色/用户群体？
2. **在哪用** — 哪个页面/哪个模块？
3. **何时触发** — 用户什么操作触发？什么条件？

## 多子系统检测

如果用户的请求隐含多个独立子系统（如"加个聊天功能和消息通知"），立即指出并建议拆分为多个独立 change。禁止在一个 change 中塞入不相关的功能。

## 完成标准

用户用自然语言描述了完整的操作流程和预期结果，你复述确认无误后，再进入 propose。

## 完成后

需求澄清完成，用户确认 → 调用 `os-plan`。

## 反例警示

用户说"加个导出功能"——不澄清就直接做 CSV，结果用户要的是 Excel 带格式导出。

## 示例

**用户：** "帮我加个导出功能"

**模型：**
```
[WORKFLOW] 判定表情况: 需求不明确 → 需求澄清（前置步骤 B）
[WORKFLOW] 当前阶段: 前置步骤 B（需求澄清）
[WORKFLOW] 前置条件: 待确认

先确认最核心的问题：导出什么数据？用户列表、订单、还是公告？
（优先给多选题）A. 订单  B. 用户  C. 公告  D. 其他
```

**用户：** "订单"

**模型：**
```
[WORKFLOW] 当前阶段: 前置步骤 B（需求澄清，第 2 轮）

明白了。接下来：导出格式偏好？A. CSV（简单无格式） B. Excel（带表头格式，支持筛选/排序）
```

**用户：** "Excel，要带表头格式，支持当前筛选结果"

**模型：**
```
[WORKFLOW] 当前阶段: 前置步骤 B（需求澄清，第 3 轮）

清楚了。最后一个问题：触发方式？
A. 订单列表页顶部加"导出"按钮（导出当前筛选结果）
B. 后台管理菜单里的批量导出功能
```

**用户：** "列表页加按钮就行，导出当前筛选的"

**模型：**
```
[WORKFLOW] 判定表情况: 需求不明确 → 需求澄清完成 → 转新功能流程 → propose
[WORKFLOW] 当前阶段: Propose
[WORKFLOW] 前置条件: 需求已澄清（订单列表页 Excel 导出，当前筛选结果，运营人员使用）

明确了：给运营人员在订单列表页使用，点击按钮导出当前筛选条件的订单为 Excel 文件（带格式表头）。单一功能在列表页触发。

符合新功能流程，我现在创建 proposal。
```
