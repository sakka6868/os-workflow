# os-scope：需求澄清 + 范围界定

## 何时调用

新功能、API 变更、任何描述少于一句话或涉及多模块交互的请求。需求不明确时优先调用。

## 核心原则

**一次只问一个问题，使用 `AskUserQuestion` 工具让用户点选。** 不要一次性抛出一串问题，不要用纯文本让用户打字回复。每轮调用一次 `AskUserQuestion`，用 `multiSelect: false`，每个选项含简短 label 和 description。能列出 2-3 个选项的优先用选择题，降低用户回答成本。

## 场景三问（逐个用 AskUserQuestion 问）

1. **给谁用** — 目标角色/用户群体？
2. **在哪用** — 哪个页面/哪个模块？
3. **何时触发** — 用户什么操作触发？什么条件？

## 多子系统检测

如果用户的请求隐含多个独立子系统（如"加个聊天功能和消息通知"），立即指出并建议拆分为多个独立 change。禁止在一个 change 中塞入不相关的功能。

## 完成标准

用户用自然语言描述了完整的操作流程和预期结果，你复述确认无误后，再进入 propose。

## 完成后

需求澄清完成，用户确认 → 调用 `os-plan`。

## 反例警示

用户说"加个导出功能"——不澄清就直接做 CSV，结果用户要的是 Excel 带格式导出。

## 示例

**用户：** "帮我加个导出功能"

**模型：**
```
[WORKFLOW] 判定表情况: 需求不明确 → 需求澄清（前置步骤 B）
[WORKFLOW] 当前阶段: 前置步骤 B（需求澄清）
[WORKFLOW] 前置条件: 待确认
[WORKFLOW] 应调用 skill: os-scope

（调用 AskUserQuestion，header="导出对象"，选项：A.订单 B.用户 C.公告 D.其他）
```

**用户点选"订单"**

**模型：**
```
[WORKFLOW] 当前阶段: 前置步骤 B（需求澄清，第 2 轮）

（调用 AskUserQuestion，header="导出格式"，选项：A.CSV B.Excel带表头格式）
```

**用户点选"Excel"**

**模型：**
```
[WORKFLOW] 当前阶段: 前置步骤 B（需求澄清，第 3 轮）

（调用 AskUserQuestion，header="触发方式"，选项：A.列表页导出按钮 B.后台批量导出）
```

**用户点选"列表页按钮"**

**模型：**
```
[WORKFLOW] 判定表情况: 需求不明确 → 需求澄清完成 → 转新功能流程
[WORKFLOW] 当前阶段: Propose
[WORKFLOW] 前置条件: 需求已澄清（订单列表页 Excel 导出，运营人员使用）
[WORKFLOW] 应调用 skill: os-plan

明确了：给运营人员在订单列表页使用，点击按钮导出当前筛选条件的订单为 Excel 文件（带格式表头）。单一功能在列表页触发。进入 propose。
```
